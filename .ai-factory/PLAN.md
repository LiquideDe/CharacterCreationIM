## Цель и границы первой версии

Создать бесплатное desktop-приложение для частных игр: мастер импортирует 2D-карту, размечает полигональные зоны и активные области, размещает NPC и токены игроков, вручную открывает и скрывает зоны туманом войны, а игроки подключаются к сессии и управляют только своими персонажами. Общая граница двух зон образует переход между ними; мастер является авторитетным хостом, управляет NPC, картой и правилами. Поддерживаются действия, атаки, эффекты и синхронная фоновая музыка. Голос добавляется после устойчивого игрового соединения.

MVP — VTT-движок с подключаемыми данными правил. Карточки талантов, характеристик, психосил и иных правил из существующих JSON поставляются с клиентом; пользователь также может импортировать собственный content pack. Перед публичным релизом владельцы проекта отдельно подтверждают правовой статус и право на распространение поставляемых rule content.

## Зафиксированные предположения

- Базой остаётся Unity 6 / C#; существующий character creator сохраняется и не ломается.
- Начальная целевая платформа — Windows; соединения рассчитаны на 2–8 участников в частной комнате.
- Код проекта планируется распространять с открытой лицензией (предварительно MIT); пользовательские кампании и музыка остаются у их авторов.
- Первичная модель доступа — без аккаунтов: мастер создаёт комнату, игрок вручную вводит его адрес и порт, затем получает назначенную роль по invite-коду.
- Бюджет MVP — нулевой: кампания раздаётся мастером как ZIP любым удобным способом, а мастерский клиент становится игровым хостом. ВМ появляется только как необязательная поздняя помощь для NAT/CGNAT и встроенного голоса.

## Архитектурная опора

Подробные границы, схема синхронизации и инфраструктура описаны в `.ai-factory/ARCHITECTURE.md`. Краткая последовательность данных:

```text
Ввод игрока -> команда -> проверка у хоста-мастера -> событие/новая ревизия
            -> сетевой patch/snapshot -> отображение у всех клиентов

Мастерский редактор -> campaign package (JSON + ресурсы + hashes)
                  -> загрузка/валидация у хоста -> раздача клиентам
```

## Инфраструктурные варианты и решение

| Вариант | Что работает | Стоимость | Ограничения | Рекомендация |
|---|---|---:|---|---|
| LAN | игра, карты; голос отдельно | 0 | только одна сеть | первый внутренний прототип |
| ZIP кампании + мастер + port forwarding | игра без постоянной ВМ; в сети только JSON/снимки | 0 | сложный NAT, адрес/порт нужно сообщать, участники вручную обновляют кампанию | рекомендуемый MVP |
| Российская ВМ + signalling/coturn/LiveKit | стабильнее join и встроенный голос | стоимость ВМ/трафика | нужна эксплуатация и домен | только после MVP или при проблемах NAT |
| Полное облако с аккаунтами | каталог/постоянные кампании | выше | лишняя сложность, персональные данные | не раньше после MVP |

Yandex Cloud подходит как один из вариантов размещения российской ВМ, но он не является обязательным и не следует считать его постоянно бесплатным: оплата Compute Cloud зависит от ресурсов и времени работы, а исходящий трафик имеет условия тарификации. Поэтому конфигурация не должна зависеть от его API и должна запускаться у любого провайдера с Docker и публичным IP.

## Необходимые отдельные планы перед началом кода

1. **Vertical slice локального VTT:** Фазы 1–2, без сети, с картой/токенами/зонами/сохранением.
2. **Сетевой прототип без ВМ:** задача 0.3 + Фаза 3.1, прямое подключение `host:port`, ручной port forwarding, проверка NAT в условиях РФ и понятная диагностика CGNAT.
3. **Модель кампании и редактор:** schema, map authoring, миграции, импорт ресурсов и редактор UX.
4. **Авторитетное боевое ядро:** команды, revisions, effects, action engine, журнал и replay.
5. **Голос и развёртывание:** LiveKit/coturn, токены, Compose, мониторинг и сценарии отказа.
6. **Правовой/релизный контур:** лицензия кода, third-party notices, политика контента, приватность и публичная документация.

- Будет ли у мастера возможность вручную открыть порт/запустить Docker, или интернет-режим обязан работать без каких-либо настроек сети у него?

## Проверенные источники для выбора стека

- FishNet допускает authoritative server, listen-server/dedicated server и бесплатное использование без лимита CCU: https://fish-networking.gitbook.io/docs
- LiveKit Unity SDK поддерживает self-hosted server и Unity 6; media server можно запустить самостоятельно: https://livekit.github.io/client-sdk-unity/index.html и https://livekit.com/pricing
- coturn — свободная реализация STUN/TURN с поддержкой UDP/TCP/TLS/DTLS: https://github.com/coturn/coturn
- Yandex Compute Cloud тарифицируется по ресурсам/времени и имеет условия для исходящего трафика: https://yandex.cloud/ru/docs/compute/pricing
- Официальные материалы IM указывают права Games Workshop/Cubicle 7 и запрет воспроизведения без разрешения: https://cubicle7games.com/en_EU/downloadable/download/sample/sample_id/168/
